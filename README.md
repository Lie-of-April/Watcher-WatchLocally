# Watcher — 本地媒体资源管理器

> 以 **图片 / 视频 / GIF 浏览** 为核心的本地媒体资源管理器。
> 版本 `0.1.0-alpha.1`
> 全是AI跑的嘿嘿  反正他能用还挺好用
> 注意，当前版本的标签信息和缓存是写在项目目录中的，并不在c盘用户信息中，对于有维护与移植需求的人来说是好的，但有像长期使用的人的话，但凡删除程序那么你的所有标签都会丢失！

## 第一部分：使用介绍与特色说明

### 这是什么
Watcher 是一个安装在你电脑上的桌面软件（非网页、非云服务），用来集中浏览、整理你本地的图片、视频和 GIF 动图。它不把你的文件上传到任何地方，所有数据都保存在你电脑上。

### 三分钟快速上手
1. **添加媒体文件夹**：首次打开（或左侧栏为空时）点击「添加媒体库」，选择你存放图片/视频的文件夹。你也可以直接把文件夹 **拖拽** 进主窗口来添加。
2. **浏览**：主区域以瀑布流缩略图展示内容。左侧栏可在不同媒体库、收藏、标签、播放列表之间切换。
3. **查看大图 / 播放**：**双击** 任意缩略图打开查看器（Viewer）。图片可缩放/平移，视频可播放/快进/调音量，漫画式套图可纵向无缝滚动阅读。
4. **整理**：右键任意条目可「加标签」「评分」「收藏」「设为套图」「重命名」「移动 / 复制」「加入播放列表」等。

### 特色
- **零原生依赖、纯本地**：缩略图在渲染进程用 canvas 解码、视频截首帧；视频拖拽进度靠自建协议 + HTTP Range 实现，不依赖任何外部服务或后台进程。
- **漫画式阅读（套图）**：把文件夹标记为「套图」后，进入纵向无缝滚动的漫画模式，并 **记忆每个套图的阅读模式与阅读进度（页数）**。
- **双阅读模式**：横向翻页（滚轮左右切图、Ctrl+滚轮缩放）与漫画纵向滚动，随心切换且各自记忆。
- **标签系统**：支持标签分组、颜色、按标签多重筛选（`同时 / 任一 / 排除`），并可导出/导入。
- **评分与收藏**：1–5 星评分、收藏夹，快速筛选「已评分」「未打标签」「仅图片 / 仅视频」。
- **跨文件夹搜索**：建立全局索引后可在「全部媒体库」中按文件名、标签、评分联合搜索。
- **每文件夹独立排序记忆**：名称 / 修改时间 / 创建时间 / 大小 / 随机 / 评分，升/降序，各自记住。
- **集中式文案（可汉化 / 多语言）**：所有界面文字集中在单一文件 `src/i18n/strings.ts`，方便你自由修改文本或制作其他语言版本（详见第三部分）。

## 第二部分：功能说明与热键说明

### 一、功能模块说明

#### 1. 媒体浏览
- 瀑布流缩略图（MasonryGrid），自动按宽高比排版。
- GIF 角标提示动图；悬停可播放 GIF / 视频 / JPG / WebP（在「设置 → 显示选项」中开关）。
- 侧边栏可整体收起、可鼠标拖拽调宽（宽度存于 `localStorage`）。

#### 2. 查看器（Viewer）
- **图片 / GIF**：缩放（按钮、滚轮、热键）、平移（拖拽或按住空格）、适应窗口。
- **视频**：播放/暂停、快进/快退、音量、倍速、循环、列表连播、全屏；底部胶片条可浏览整个列表。
- **信息面板**：显示文件名、路径、类型、大小、修改时间、尺寸、时长、EXIF、评分、标签。

#### 3. 阅读模式
- **横向（horizontal）**：默认模式，滚轮左右切图，Ctrl+滚轮缩放当前图。
- **漫画（manga）**：纵向无缝滚动，Ctrl+滚轮缩放页宽（30%–400%），缩放时锁定当前页视觉中心；**记忆每套图的阅读模式与进度**。

#### 4. 套图（Album）
- 把任意文件夹标记为「套图」，即以漫画式纵向阅读；可为套图指定封面，套图封面会并入其评分展示。

#### 5. 标签（Tags）
- 分组管理、颜色区分、未分组归并。
- 给文件 / 文件夹打标签；按标签筛选支持「同时 / 任一 / 排除」三种逻辑。
- 标签与元数据可 **导出 / 导入（合并）**。

#### 6. 收藏与筛选
- 收藏夹；快速筛选「收藏」「未打标签」「仅图片」「仅视频」。

#### 7. 播放列表（Playlists）
- 视频播放列表：新建、重命名、删除、上下移动排序、清空、从选中项添加。

#### 8. 搜索
- 文件名搜索；建立全局索引后可跨「全部媒体库」搜索。
- 范围限定：当前文件夹 / 全部媒体库。
- 联合条件：标签多选（and/or/not）、评分筛选、「已评分」。

#### 9. 排序
- 维度：名称 / 修改时间 / 创建时间 / 大小 / 随机 / 评分。
- 方向：升序 / 降序；**每文件夹独立记忆**。

#### 10. 评分
- 1–5 星；网格右键菜单可 1–5 星 + 清除；查看器数字键 1–5 评分；套图封面并入学评分。

#### 11. 视图选项（设置 → 显示选项）
- 显示文件夹、文件夹排在前面、包含子文件夹内容、自动生成文件夹封面、GIF/视频/JPG/WebP 悬停播放、缩略图大小（140–420px）。

#### 12. 设置（Settings）
- **外观**：主题（亮 / 暗）、强调色、缩略图宽度、图像采样（双线性 / 最近邻）、卡片间距。
- **浏览**：默认排序、确认删除、缩放灵敏度、拖动步长（seekStep）、预览保持（previewHold）、总是循环。
- **数据**：标签与元数据导出 / 导入（合并）。

#### 13. 右键 / 上下文菜单
打开文件夹、查看、收藏 / 取消收藏、添加标签、评分（N 星 / 清除）、加入播放列表、设为父文件夹封面、选取封面、恢复封面、设为套图封面、重命名、移动到、复制到、在资源管理器中显示、删除、设为 / 取消套图。

#### 14. 框选（Marquee）
- 在空白处 **左键拖拽** 框选；Shift 拖拽同样可用；连续框选 = 并集，反选 = 取消。

#### 15. 选择与拖拽
- 单击选中单个；Ctrl / Cmd + 单击切换选中；可直接把文件 / 文件夹拖入窗口添加为媒体库。

## 第三部分：开发者 / 贡献者信息

> 面向想要阅读源码、修 Bug、新增功能或制作语言包的程序员。

### 技术栈
- **Electron 33** + **Vite 5** + **React 18** + **TypeScript 5**。
- 零原生依赖：缩略图在渲染进程用 canvas 解码 / video 首帧截取；视频拖拽进度靠自建 `media://` 协议 + HTTP Range。
- 数据存储：集中式 JSON 库（`Store`），位于 `userData/data`，不污染媒体文件夹。

### 目录结构
```
watcher/
├─ electron/                   Electron 主进程
│  ├─ main.js                  窗口 / 协议 / 生命周期
│  ├─ preload.js               contextBridge → window.api
│  ├─ ipc.js                   通道注册（H('ns:fn')）
│  └─ lib/                     store / thumbs / fsops / indexer /
│                              media-protocol / dbapi / animflag / consts
├─ src/                        渲染进程（React）
│  ├─ main.tsx                 入口
│  ├─ App.tsx                  顶层集成
│  ├─ store/AppContext.tsx     全局状态 useApp
│  ├─ i18n/strings.ts          ★ 集中式界面文案（单一事实来源）
│  ├─ components/              TitleBar / Sidebar / Toolbar / MasonryGrid /
│  │                           Cards / Thumb / Viewer / MangaStrip /

```

### ⚠️ 文本（i18n）强制约定 —— 以后涉及文本必须走这里
**所有用户可见文字都集中在 `src/i18n/strings.ts`（单一事实来源）。任何新功能、新提示、新按钮，凡涉及界面文本，都必须在此文件登记，绝不允许在组件里写死中文/英文字符串。**

约定细则：
1. 组件引用方式：
   ```ts
   import { t } from '@/i18n/strings'
   // 普通
   t('namespace.key')
   // 带占位符（动态文案用 {var} 占位）
   t('app.dropHint', { dir: entry.name })
   ```
2. `strings.ts` 中按命名空间归类（`titlebar.*` `sort.*` `view.*` `toolbar.*` `sidebar.*` `cards.*` `thumb.*` `tags.*` `playlist.*` `viewer.*` `ctx.*` `app.*` `settings.*` `empty.*` `misc.*`）。新增文本时找对应命名空间追加一行：
   ```ts
   'namespace.newKey': '中文文案',
   ```
   需要插值就写成 `'app.dropHint': '把 {dir} 拖进来'`。
3. `t(key, vars?)` 的 fail-safe 行为：**未定义的 key 会原样返回 key 本身**。所以开发时若界面出现原始 key 字符串（如 `ctx.deleteN`），说明漏在 `strings.ts` 里加这条 key —— 补上即可。
4. 该约定已在 `strings.ts` 文件头注释中标明，请后续开发严格遵守，保持单一文案来源，便于汉化与多语言。

### 新增 IPC 通道（三步，缺一不可）
主进程与渲染进程通信必须改三处，否则 TypeScript 不报错、只在运行时炸 `is not a function`：
1. `electron/ipc.js` 注册：`H('ns:fn')`
2. `electron/preload.js` 暴露：`invoke('ns:fn')`
3. `src/lib/api.ts` 封装：`call<T>()`

自检（两段输出都为空才算对齐）：
```bash
grep -oP "H\('\K[^']+" electron/ipc.js | sort > /tmp/a
grep -oP "invoke\('\K[^']+" electron/preload.js | sort -u > /tmp/b
comm -23 /tmp/a /tmp/b   # ipc 有、preload 无
comm -13 /tmp/a /tmp/b   # preload 有、ipc 无
```
